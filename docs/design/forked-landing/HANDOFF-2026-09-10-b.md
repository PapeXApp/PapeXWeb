## 2. What changed this session

### 2.1 The axe in the /customers flip cards (`6e74f89`)

Nico's "the axe looks weird" was three separable defects, found by stepping the animation frame by
frame with `.claude/tools/burst`-style capture rather than watching it:

1. **Scale.** `AXE_SCALE 0.9` put the axe at ~85 units against trees of 76–118 — the head was as wide
   as a canopy. Now `0.64`.
2. **The down-swing was invisible.** 135° → −18° ran in 220ms, two or three frames, so the axe
   appeared already planted in the wood. The strike now gets 300ms of a 620ms lead.
3. **The dominant motion was a slide.** The sweep was the longest leg at 760ms and rotated only 8°
   across it, so a near-upright axe travelled the row like a cursor. Now 520ms, following through
   −14° → +16°, which scythes.

Shortening `SWEEP_MS` also tightens each tree's `fellDelay`, so the row falls as one wave off the
impact instead of a nine-beat domino. Entry and exit were also pops and are eased now.

Files: `components/paths/customer/FlipCards.tsx`, `flipcards.module.css`. The CSS keyframe comment
carries the percentage arithmetic — **update it if you change the timing constants**, the two are
only kept in sync by hand.

### 2.2 Feature shots 04.1 / 04.2 (`55fddee`)

Will: "the images at 4.1 get cut off." The `.featShot` cell aligned the phone to its **bottom** edge,
so the 84px of overflow started at the top and `translateY(9%)` only pushed about half of it back
down. The crop landed on both edges: 41px off the top, 43px off the bottom. Losing the top took the
bezel, the notch and the corner radius — the parts that make it read as a phone — so it stopped
looking cropped and started looking broken.

Fix: top-align the device so every pixel of overflow falls past the bottom, which is what the comment
above it always claimed. `translateY(4%)` keeps a little air above.

Sizing: `112cqh` left 109px of empty screen under the last list row (27% of the card); `132cqh` puts
the crop just below it.

That deeper crop breaks the share sheet, which is anchored to the **bottom** of the device — at
132cqh its whole action list was off-frame. **`--wp-sheet-lift`** raises a bottom-anchored layer to
the crop line, so the sheet is flush with the *visible* edge instead of the device edge. The device
bottom is never on screen, so the substitution is invisible. `ShareSheetShot` passes `sheetLift="40cqh"`;
top-anchored screens leave it unset.

### 2.3 Business section 02 — the crumple receipt (`f99fba1`, then `b8d64e8`)

Replaces the static 2×2 stat grid. A thermal printer feeds out a receipt whose line items ARE the
four claims — the amount column of a receipt is exactly the shape of `$0` / `1 port` / `1 tap` /
`0 rolls`. Drag the paper to crumple it, flick it at the bin.

`f99fba1` built it with payoff cards underneath. **`b8d64e8` removed the cards on Will's direction:
the receipt is the section, full height, one point at a time, large type.** Read the second commit,
not the first — the first is only useful for the reasoning it records.

Things that are load-bearing and will look like arbitrary numbers:

- **The slip renders COMPLETE on the server and the client rewinds it to an empty slot on mount.**
  With no cards underneath, the receipt is the only copy of the claims, so it has to survive a
  crawler and a visitor who never plays. Verified in the no-JS HTML. Do not "optimise" the initial
  state to empty.
- **Reduced motion never rewinds**: finished slip, no printer, no prompt, nothing grabbable.
- **The stage is 820px, not the 1150 column.** A receipt is inherently ~2:1, so at full column width
  the slip sat at 25% of the frame with a 426px void beside it. Narrowing the stage is what makes it
  dominate; widening the scene only buys more emptiness. This was measured, not guessed.
- **Printing is six beats driven by the slip's own height**, not a clip-path unmasking a fixed sheet,
  so the paper genuinely lengthens out of the slot.
- **Crumple completing mid-drag hands the same gesture over to carrying the ball** (`setDrag({x:0,y:0})`
  plus keeping `last.current`). Without that you are left holding a ball that ignores you until you
  release and re-grab.
- **A throw needs `CARRY_TO_THROW` (34px) of travel.** Releasing the instant it balls up leaves it in
  hand, which is what keeps "now flick it at the bin" as its own beat.
- **A thrown ball always lands** — the arc corrects for wherever it was released. No miss state.
- **Crumple is five stepped `feDisplacementMap` levels**, not a filter animated per frame. Paper
  creases in jumps and the smooth part is the transform, which is free.
- **After the throw the scene shrinks 125cqw → 52cqw.** This was my judgment call, not Will's
  instruction — the slip's column is empty at that point and a thousand pixels of nothing was worse.
  Open for Nico.

Also removed `.wcard` / `.wcardLead`, dead with the grid they styled.

## 6. Traps

- **Never `npm run build` while `npm run dev` is running** — shared `.next`, every route 500s.
  Recover: stop the server, `rm -rf .next`, restart. During dev use `npx tsc --noEmit` and
  `npx next lint --file <path>`.
- **`npx tsc --noEmit` reports 8 errors that are not yours.** They are all in
  `.next/types/app/blog/**`, dated Aug 18, referring to `app/blog/<slug>/page.js` files that do not
  exist — blog is a `[slug]` dynamic route and those are stale stubs from an older static-blog build.
  Filter with `grep -v '^\.next/types'`. `rm -rf .next` clears them, but only with the server stopped.
- `npm run lint` has 20 pre-existing failing files (listed in `CLAUDE.md`), none in the redesign
  folders. Keep it that way; lint per-file.
- **CSS Modules will not rename a keyframe inside an `animation` shorthand that also contains a
  `var()`.** Every animation in `business.module.css`'s crumple block sets `animation-name` on its own
  line for this reason. Do not collapse them into shorthands.
- `Reveal` writes an inline transform, so wrap cards: the wrapper takes the reveal, the card keeps
  `:hover`.
- The merchant dashboard is subdomain-only; **a 404 at `/merchant` on the main host is correct.**
- `/r` is a real route and a Server Component on purpose; the AASA file and its headers in
  `next.config.ts` must not break — App Clip launches depend on them.
- `setPointerCapture` throws for a pointerId the browser no longer considers active. The crumple
  scene guards it in a try/catch; an unguarded throw kills the gesture before it starts.

## 7. Verification toolkit

Dev: start `papex-merchant` from the **workspace-root** launch.json (see §0C), then
`http://localhost:3000/business`.

Headless Chrome scripts in `.claude/tools/` (Node 22, no deps, viewport-by-viewport so scroll reveals
fire). The first four predate this session, the last three were added by it:

```bash
node .claude/tools/shoot.mjs   <url> <outPrefix> [w] [h] [max]      # full page, in viewport slices
node .claude/tools/shootAt.mjs <url> <prefix> <w> <h> <y1,y2|footer:OFFSET,...>
node .claude/tools/shootflip.mjs <url> <prefix> [w] [h] [ms,...] [reduced]   # clicks the flip cards
node .claude/tools/gap.mjs                                          # section gaps at 1440

node .claude/tools/shootel.mjs <url> <out.png> <selector> [n] [w] [h] [pad]  # clip to one element, 2x
node .claude/tools/sheet.mjs   <out.png> <cols> <in.png...>         # tile frames into one contact sheet
node .claude/tools/crumple.mjs <url> <outPrefix> [w] [h]            # drive business 02 through all six beats
```

`selector` is matched with `querySelectorAll`, so CSS Module hashes are reachable as
`[class*="crPaper"]`.

**`sheet.mjs` is the one that changes how you work on animation.** Reading an animation one PNG at a
time is how the axe stayed broken; tiling twenty frames into one image is how all three defects
became obvious in a single look. Burst the frames, then sheet them.

**`crumple.mjs` proves the gesture, not the pixels.** Section 02 is pointer-driven, so a static
screenshot proves nothing. It synthesises the real drag and asserts two things a screenshot cannot:
that releasing straight after the crumple does NOT throw, and that the flick does.

**The gate used for every round this session:** `tsc` clean on source (see the `.next/types` filter
above) + per-file lint 0 + `/`, `/customers`, `/business` all 200 + real-Chrome captures at 1440×900
**and** 390×844 + reduced-motion check + for section 02, the claims present in the no-JS HTML
(`curl -s localhost:3000/business | grep -cF '0 rolls'`).
